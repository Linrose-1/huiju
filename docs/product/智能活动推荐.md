# 会聚｜智能活动推荐首版需求

日期：2026-10-02。状态：产品规则已逐项确认，首版代码与接口契约已接入；工程验证见[10月实现记录](../implementation-log/2026-10.md)。依据[首期 PRD F07](首期PRD.md)；技术设计见[智能活动推荐技术方案](../architecture/activity-recommendation.md)。迁移、真实模型与人工验收未执行，本文不代表接口已在运行环境开放。

## 1. 目标与入口

首版做“我说需求，AI 帮我找活动”，不做打开页面即自动生成的个性化信息流。用户输入自然语言需求，获得平台已有活动及简短推荐理由，继续补充条件后重新筛选，自主查看详情和报名。

助手页“帮我找活动”、活动页“推荐”进入同一个独立页面。页面以本次对话、理解到的条件、活动卡片和底部输入区组成；原生导航标题为“帮我找活动”。入口替换现有未开放提示，不新增另一套报名流程。

## 2. 身份与资料

- 必须登录后使用。有效会员会话即可，不要求先绑定手机号、主动设置头像和名称。
- 资料不完整仍可检索，缺少辅助资料时按本次输入匹配。已有资料可用于站内辅助，不以完整度决定是否能找活动。
- 结果区提供可跳过的轻引导，例如“完善你的资源与需求，推荐会更贴合你”，附“去完善”入口，不弹窗打断或强制跳转。
- 完善资料后返回当前找活动页面，保留对话、条件和已加载结果；资料保存不自动重新检索或消耗额度。
- 报名继续执行既有手机号、头像、名称完整度门槛。登录与完善资料是不同目的，返回行为不能混用。

## 3. 对话与条件

- 本次明确输入优先，个人资料只能辅助，不能覆盖用户指定的城市、时间、费用等要求。
- 必选条件严格筛选；“最好”“优先”等偏好用于排序。例如“下周在深圳，最好免费”：下周、深圳为必选，免费为偏好；“只看免费”则为必选。
- 结果上方简短展示理解到的条件，用户可继续输入以纠正或补充。缺少的条件不擅自补成限制。
- 需求宽泛时先给结果，不先做长问卷；条件相互矛盾时简短追问。不能可靠理解的关键限制不得静默忽略。
- 补充条件触发新的检索，从首批结果开始；上一轮未完成请求不能覆盖新一轮。
- 只保留本次会话，暂不做历史会话列表。去详情、报名或完善资料再返回时保留上下文；退出账号或切换身份、API环境后清除旧身份的会话。

## 4. 推荐范围与结果

- 默认只推荐当前可报名活动：已发布、未取消、未下架、未截止且有剩余名额；不推荐本人已报名或本人发起的活动。
- 每批最多3个活动，展示名称、时间、地点、费用、具体理由和“查看详情”。不足3个按实际数量显示，不凑数。
- 理由必须有活动内容依据；不承诺一定认识某类人、获得合作或商业回报。偏好未满足时明确展示差异，例如收费活动不掩盖其费用。
- “查看更多”每次追加最多3个，不重复展示、不重新调用AI、不消耗检索次数；追加失败保留已有结果并允许重试。
- 修改条件后重新检索，结果分页归零。没有更多时明确提示。
- 没有匹配活动时明确说明，可建议用户调整条件；必须由用户主动调整，不自动放宽时间、地点或其他必选条件，不编造活动。
- 推荐展示不锁定名额；活动状态变化后，以打开详情及提交报名时的实时校验为准。

## 5. 数据使用

- 外部AI仅接收用户本次找活动输入及候选活动公开信息。连续对话所需的用户主动输入上下文与其明确条件属于本次会话；不得混入从会员资料推导出的隐性条件。
- 本人的资源、需求、家乡、简介、浏览和报名记录仅在会聚服务端辅助匹配，不把这些资料或行为原文交给外部AI。
- 不公开资源、需求可以用于向本人推荐，不能出现在其他会员可见内容或分享信息中。
- 手机号、真实姓名、邮箱和邀请上下级关系不参与匹配；活动咨询联系方式、报名联系方式与答案不得作为“公开活动信息”发送。
- 推荐页面不将会员资料原文回显为推荐理由；理由优先引用活动公开信息及用户本次明确条件。

## 6. 额度与失败

每位登录会员每天最多成功检索10次，按北京时间自然日重置，与活动草拟每天5次独立计算。

| 行为或结果 | 次数规则 |
| --- | --- |
| 首次需求成功返回结果 | 计1次 |
| 补充条件后成功重新检索 | 计1次 |
| 成功检索但无匹配活动 | 计1次 |
| 点击查看更多 | 不计次，不重复调用AI |
| 模型超时、失败或响应无法使用 | 不计次，用户主动重试 |
| 达到当日上限 | 不能发起新检索，仍可查看已有结果和浏览全部活动 |

失败时保留用户输入，明确提示暂时无法智能匹配，提供“重试”和“浏览全部活动”。不自动重试、切换模型或把普通列表包装成智能结果。

## 7. 直接归因

- 分别记录推荐展示、推荐后的直接查看和直接报名，首期不承诺固定准确率。
- 用户从本次推荐卡片进入详情，并沿该路径完成报名，才计作本次推荐带来的报名。
- 分享给他人、后来从普通活动列表进入并报名，不归因于这次推荐。资料完善是原报名流程的一部分，不能无故丢失直接来源。
- 归因仅用于效果统计，不改变报名资格、价格、名额或活动规则；不新增统计后台页面。

## 8. 首版验收条件

1. 两个入口进入同页；匿名需登录，登录但资料不足可检索，报名仍校验完整资料。
2. 明确城市、时间、费用等必选条件不被个人资料或偏好覆盖；条件展示可纠正，矛盾不静默执行。
3. 取消、下架、截止、满员、本人发起及本人已报名活动不进入可报名推荐；打开详情前后的状态变化被处理。
4. 每批不超过3条，查看更多不重复、不调用AI；新条件清新结果而非混入旧列表，分页失败可重试。
5. 提供有依据的理由；不足和无结果如实呈现，不虚构候选或自动放宽条件。
6. 对外载荷不含站内个人资料、行为记录及排除字段；不同会员不能读取对方查询、结果或直接来源凭据。
7. 每日成功10次上限跨进程有效；失败不计、无结果计、查看更多不计，跨日及响应丢失不重复扣次。
8. 完善资料／详情返回保留会话；换号和环境切换清理，迟到响应不恢复旧身份内容。
9. 推荐直接查看与真实报名可分别核对，普通列表、分享和伪造来源不增加归因统计。

## 9. 范围与状态

本次不包含历史会话列表、自动推荐信息流、外部活动采集、后台推荐分析页面、付费推荐或自动报名。
