# 会聚｜首期产品需求文档（PRD）

版本：0.3（可验收草案）

日期：2026-09-28

依据：[会聚首期需求草案](首期需求草案.md)及本次逐项确认。本文定义产品行为和验收条件；未定事项列在文末，不视为已批准的实现细节。

## 1. 产品目标

会聚服务于地产教育机构及其学员群体。会员通过活动浏览、发起、分享、报名和参与建立联系，逐步填写个人资料、资源与需求；机构通过后台了解会员参与情况，并管理活动与会员信息。

首期交付形态：微信小程序、管理后台，以及两端共用的业务数据。具体技术架构另行设计。

### 用户角色

| 角色 | 首期主要任务 |
| --- | --- |
| 浏览用户 | 从分享入口查看活动、阅读留痕和报名列表；按需完成个人资料 |
| 已完善资料会员 | 报名、发起和分享活动，评论与点评，查看允许公开的会员资料 |
| 活动发起人 | 管理自己活动的报名问题、报名信息、签到与活动数据 |
| 超级管理员 | 查看会员及活跃度、管理活动和违规评价、维护运营文案；管理运营账号及指定小程序文案编辑权限 |
| 普通运营 | 受信任的内部工作人员；查看完整会员资料及活跃度、管理活动和违规评价、维护后台运营文案 |

本文统称两类后台角色为“平台管理员”；后台身份与小程序会员身份独立，后台角色不自动获得会员身份或小程序文案编辑权限。

## 2. 首期边界

**包含：** 邀请关系、静默身份识别、渐进资料、免费与收费两种活动模式（平台不收款）、分享、报名与自定义问题、阅读留痕、评论和点评、手动签到、AI 活动草拟与推荐、后台会员查看和活跃度、活动下架与恢复、运营文案配置。

**不包含：** 平台内支付与资金结算、发布前审核、会员禁用、会员自行修改已绑定手机号、管理员直接纠正会员资料或邀请关系、独立申诉页面。1.5 与 2.0 的规划见[版本路线图](版本路线图.md)，不计入首期验收。

## 3. 核心流程

1. 会员分享活动，入口携带活动标识和分享者邀请码；没有邀请码来源的新用户归属平台最高级邀请码。
2. 新用户打开活动即可浏览。小程序尝试静默建立微信身份；识别成功时创建或读取平台用户，并按首次有效来源固定邀请上级。
3. 用户需要报名、发起活动、评论或点评时，先完成绑定手机号、用户头像、用户名称。平台默认头像和用户编号名称不算完成资料。
4. 会员选择免费或收费模式发起活动，可用 AI 草拟内容，自己确认后直接发布；其他用户通过分享入口浏览、报名。收费活动不在平台内收款。
5. 活动发起人查看报名和阅读数据，手动标记到场；平台管理员查看会员活跃度，必要时下架活动。

## 4. 功能需求与验收条件

### F01 邀请与身份

会员编号：新会员首次建立身份时生成 `HJ`＋北京时间注册日期（YYYYMMDD）＋当日六位顺序号，例如 `HJ20260928000001`。每天从 `000001` 开始；重复登录保持原编号。内部 UUID 与邀请码仍独立。历史会员按注册日期、注册时间先后统一为新格式；时间相同时按内部 ID 排序。编号不作为内部关联键。

**需求**

- 微信好友、微信群及朋友圈分享活动时携带分享者邀请码。
- 新用户首次以有效邀请码进入平台后绑定邀请上级；绑定后不因后续分享入口改变。无邀请码来源时绑定平台邀请码。
- 小程序尝试静默取得微信侧身份标识，与平台用户建立关联。身份暂时无法识别时仍可浏览活动。

**验收条件**

1. 新用户分别从有效邀请码和无邀请码入口进入，后台可查到对应的上级会员或平台根节点。
2. 已有邀请关系的用户再次打开另一分享者的活动，邀请上级保持原值。
3. 未完成资料或身份识别暂时失败时，活动详情仍可打开；受限操作不能越过资料门槛。
4. 朋友圈单页模式与正式进入小程序的邀请绑定时点，在真机验收中分别检查。

### F02 个人资料与可见范围

**需求**

- 资料字段：用户头像、用户名称、真实姓名、邮箱、家乡、我有资源、我需资源、个人简介；绑定手机号作为会员数据单独取得。
- 报名、发起活动、评论、点评前必须完成绑定手机号、用户头像和用户名称。手机号绑定后首期不支持用户自行修改；其他资料可由会员维护。
- 头像、用户名称在名片及活动人员列表中始终展示。家乡、个人简介、“我有资源”“我需资源”各有独立的名片展示开关，首次均默认关闭。
- 真实姓名、邮箱、绑定手机号默认仅本人及平台管理员可见；会员可逐项主动选择在名片上向已完善三项必填资料的其他会员公开。保存名片展示设置前可预览。
- 未完善资料的浏览用户只能查看活动及公开列表中的头像、用户名称，不能打开完整会员资料页。
- 点击活动阅读留痕或报名列表中的头像，可进入该用户的名片。用户可逐项设置自己的名片展示字段；未选中字段不向其他会员开放，设置不改变原始资料。

**验收条件**

1. 仅有默认头像和用户编号名称的用户仍被判定为资料未完善；缺少任一必填项时，受限操作引导补全资料。
2. 已完善资料会员只能看到其他会员名片中开启展示的字段；资源、需求或其他字段关闭展示后，对其他会员不可见。
3. 浏览用户不能通过页面或接口取得完整名片；普通会员仅在名片主人主动开启相应字段时，才能取得其真实姓名、邮箱或绑定手机号。
4. 会员更新头像或用户名称后，已有报名列表和阅读留痕显示最新资料。
5. 已完善资料的会员从阅读留痕或报名列表点击头像，可进入对方名片；名片只展示对方允许公开的信息。资料未完善的浏览用户不能越过既有权限进入完整名片。
6. 头像和用户名称不能从名片关闭；其余七个字段首次均默认关闭，会员可独立开关，保存前能预览。主人主动开启之前，其他会员不能查看这些字段。

### F03 活动发起、分享与状态

**需求**

- 已完善资料的会员可选择免费或收费模式直接发布活动，无发布前审核。收费活动设置一个大于 0 的人民币固定金额；所有报名者价格相同，出现首个报名后金额锁定。
- 活动列表和详情明确展示免费或收费及收费金额。收费活动提交报名后立即报名成功并占用名额；收费、收款、核验、退款和费用争议均由报名者与发起人在线下处理，平台不记录付款或退款状态，也不提供付款说明或收款码。页面统一提示“本活动为收费活动，请联系活动发起人了解具体收费事宜”及“会聚不参与本活动的收费、收款和退款，相关费用请直接与活动发起人确认”。
- 必填活动信息：标题、介绍、开始与结束时间、地点、活动咨询联系方式；封面、人数上限和报名截止时间可选。咨询联系方式可填写手机号、微信号或其他文字，不区分免费和收费活动。未设置报名截止时间时，活动开始即截止报名。
- 活动咨询联系方式不在公开详情展示；发起人、平台管理员以及曾成功报名该活动的会员可以查看。本人取消报名、活动取消或活动下架后仍保留查看权。从未报名者不能通过页面或接口取得。发起人可在活动结束前修改，当前有效报名者收到站内通知，所有有权查看者读取最新内容，修改进入操作记录。
- 设置人数上限后，报满停止接受新报名；报名者取消后立即释放名额，报名截止前其他人可补报。同时报名不能超过人数上限。
- 发起人可在活动开始前取消活动，填写原因；已报名者在小程序内可查看取消通知。取消活动不批量改写报名状态或清空人数，页面显示“活动已取消，取消前已有 X 人报名”，后台保留原名单；这些报名不计作实际到场。
- 管理员可填写原因强制下架活动。下架后活动从公开列表移除，旧链接显示下架状态，停止报名和评论，后台保留原活动、报名和操作记录。已报名者在小程序内可查看下架通知。
- 下架活动只能由管理员决定恢复；发起人可通过现有联系渠道说明情况，首期无独立申诉页。恢复不自动延长原定时间；仍在报名期且有名额时可继续报名，报名已截止或活动已开始时只恢复展示和历史记录。已报名者在小程序内可查看恢复通知。
- 首期活动变动通知只保留在小程序内供已报名者查看，不做小程序外的主动提醒。

**验收条件**

1. 符合必填信息的免费和收费活动均可由会员直接发布并从分享入口打开；不经过管理员审批。列表和详情显示对应模式，收费活动显示固定金额和平台不参与费用处理的统一提示；报名过程不触发平台内支付，也不产生付款或退款状态。
2. 报名截止或报满后，新报名被拒绝且用户看到相应原因。取消报名后名额立即释放；多人同时争抢最后一个名额时，仅一人成功，活动不超额。
3. 发起人在开始前取消活动后，已报名者可在小程序内看到取消原因和通知；不依赖小程序外的主动提醒。
4. 管理员下架后，公开列表不再展示该活动；旧分享链接不能继续报名或评论；管理员可查到下架原因和历史记录。
5. 发起人不能自行恢复下架活动。管理员恢复后，未到报名截止且有名额的活动可继续报名；已截止或已开始的活动不重新开放报名，原报名记录保留，已报名者可看到恢复通知。
6. 免费和收费活动均缺少咨询联系方式时不能发布。从未报名者不能取得联系方式；曾成功报名者在本人取消、活动取消或下架后仍可查看最新联系方式。发起人在活动结束前修改联系方式后，当前有效报名者可看到站内通知。
7. 收费活动首个报名出现后不能修改收费金额。活动或报名取消只改变对应业务状态和名额，不触发平台退款流程，页面提示联系发起人处理费用。

### F04 报名与自定义问题

**需求**

- 报名前须已完成会员必填资料。报名表不重复填写头像和用户名称；默认带入绑定手机号，报名者可修改本次活动的联系手机号，不改变绑定手机号。
- 发起人可增加简答、长文本、单选和多选题，并逐题设置是否必填。第一人报名之前可修改或删除问题；已有报名后问题和选项锁定。
- 报名者可在报名截止前修改自己的自定义问题答案，在活动开始前自行取消报名。活动取消后答案永久锁定；活动下架期间暂时锁定，恢复后仅在原报名截止时间之前重新允许修改。
- 取消报名后，只要活动重新满足已发布、未取消、未下架、仍在报名期且有名额等全部条件，会员可以再次报名并重新竞争名额；系统复用同一条报名主记录并保留每次报名和取消的操作历史。
- 活动发起人可查看自己活动报名者本次提交的联系手机号和自定义答案；其他报名者不可查看。

**验收条件**

1. 报名表展示默认联系手机号；修改后仅当前报名保存修改值，会员绑定手机号保持原值。
2. 未回答必填问题不能提交；四种题型的答案均随报名保存。
3. 第一人报名后，发起人不能修改或删除问题及选项；报名者在截止前仍能修改自己的自定义答案。
4. 活动开始前报名者可取消报名；取消后不计入当前有效报名人数，并立即释放占用名额。
5. 其他报名者无法从页面或接口读取某人的联系手机号和自定义答案。
6. 会员取消后再次报名时重新校验资料、时间、活动状态和容量，并重新确认当次联系手机号与答案；曾经报名不产生名额优先权，题目也不会因取消而解锁。
7. 活动取消后不能修改答案；下架期间不能修改答案；恢复后若仍未到原报名截止时间，可以继续修改。

### F05 阅读留痕、报名列表与活动数据

**需求**

- 阅读留痕和报名列表独立展示；平台用户可查看列表中的头像、用户名称。列表使用会员当前资料，个人资料更改后同步显示新值。
- 同一用户在同一活动的阅读列表中只出现一次，按最近一次阅读排序，不展示具体阅读时间。已识别但未完善资料的用户显示平台默认头像和用户编号名称。
- 活动详情每成功打开一次计一次浏览；浏览人数按用户去重。未识别访问用设备临时访客标识去重，计入统计但暂不进入公开阅读列表；之后若能关联到用户，再补入列表。跨设备可能无法准确合并。
- 报名转化率 = 当前有效报名人数 ÷ 浏览人数。浏览人数为零时显示“—（暂无浏览）”，不显示 0%。发起人可查看自己活动的浏览次数、浏览人数和报名转化率。

**验收条件**

1. 同一用户重复打开活动时，浏览次数增加，浏览人数和阅读列表人数不重复增加。
2. 未识别访问计入浏览数据但不产生可识别的公开阅读行；身份建立后可关联的历史阅读进入列表。
3. 取消报名后，当前有效报名人数及报名转化率按定义更新。
4. 浏览人数为零时，发起人看到“—（暂无浏览）”；出现浏览后按定义展示百分比。
5. 普通浏览者能看两个列表的头像和用户名称，但不能看他人的报名联系方式或答案。

### F06 评论、点评与签到

**需求**

- 已完善资料的会员可在已发布活动下发表文字评论，查看活动的人可阅读；首期不做楼中楼回复。
- 活动结束后，只有已报名且被发起人标记到场的参加者可提交点评。点评包含 1–5 分及文字评价，向查看活动的人展示点评者头像、用户名称和评价内容；发起人可查看评分汇总。
- 会员可修改、删除自己发布的评论或点评；每位到场者对同一活动最多保留一条点评。
- 管理员可填写原因隐藏违规评论或点评，保留操作记录；活动发起人不能删除或隐藏他人的评价。
- 活动取消或被下架后停止新增评论和点评，已有内容随活动记录保留。
- 活动发起人在自己活动的报名名单中手动标记到场，报名和到场分别记录。

**验收条件**

1. 资料未完善的用户不能提交评论；符合条件的评论提交后，查看活动的人可读到，且不能发表楼中楼回复。
2. 活动未结束时、未报名或未被标记到场的用户不能提交点评；符合条件的参加者在活动结束后可提交 1–5 分和文字评价，发起人能看到评分汇总。
3. 同一到场者不能给同一活动留下两条同时有效的点评；本人可修改或删除自己的评论与点评，不能修改他人内容。
4. 管理员隐藏违规评论或点评后，公开页面不再展示该内容，后台可查隐藏原因及操作记录；发起人不能隐藏他人的评价。
5. 活动取消或被下架后不能继续提交评论或点评，历史内容仍可由有权查看活动记录的人查到。
6. 发起人可将自己活动的报名者标记到场；该行为进入后台到场统计。其他普通会员不能替发起人签到。

### F07 AI 辅助

**需求**

- 发起人可让 AI 草拟活动内容，自己检查、修改后发布；AI 不自动发布。
- “帮我发活动”首版由会员在一个普通输入框中输入整段活动想法，再主动点击“生成草稿”；可使用系统输入法自带的语音输入，不开发录音或语音识别能力。
- AI 可草拟标题和介绍，并仅从用户明确表达的内容提取开始与结束时间、地点、人数上限、免费或收费及固定金额、报名截止时间、报名问题。缺失或含糊的事实保持待填写，不推测具体日期、价格或人数；封面和活动咨询联系方式由发起人手动填写。报名问题的题型、必填与选项若不明确，仍由发起人核对。
- 生成结果直接进入现有发起活动编辑流程，不增加独立预览页。发起人可修改全部候选字段、补齐必填项，并按现有发布确认流程手动发布；生成本身不创建或发布活动。
- “生成草稿”仅供已登录且已绑定手机号、主动设置头像和用户名称的会员使用；资料不足时引导补全。每位会员每天最多成功生成 5 次，失败不计次；达到上限时明确提示。
- 首版生成失败由用户手动重试，不自动切换模型或重复调用。后端不保存原始整段输入或模型原始回复，只记录每日限额所需的会员、时间及成功状态。
- 会员可获得活动推荐及简短推荐理由。匹配可使用会员自己的资源、需求、家乡、简介、浏览和报名记录，以及活动标题、介绍、时间、地点。
- 会员设为不公开的资源与需求仍可用于向该会员本人推荐，但不向其他会员展示。匹配不使用手机号、真实姓名、邮箱或邀请上下级关系。
- 记录推荐展示后的查看和报名行为，用于评估效果；首期不承诺固定准确率。

**验收条件**

1. AI 草拟内容进入发起人的编辑流程，未经发起人确认不会成为已发布活动。
2. 一段同时包含活动内容、时间、地点、人数、费用和报名问题的输入可生成对应可编辑字段；未明确的字段保持待填写，封面和咨询联系方式不由 AI 代填。资料未完成、超出每日限额、模型失败时分别给出可理解的提示，失败不扣成功次数。
3. 推荐活动可打开详情，显示简短推荐理由；推荐展示、后续查看和报名可分别统计。
4. 推荐界面及对其他会员开放的数据不泄露设置为不公开的资源与需求，也不把排除字段用于匹配。

活动草拟的数据处理方式见[AI 活动草拟技术设计](../architecture/ai-activity-draft.md)；活动推荐的数据处理方式仍需另行核对。

### F08 管理后台

**需求**

- 后台采用超级管理员（`super_admin`）和普通运营（`operator`）两级角色。两类角色均以独立账号及密码登录，不开放自行注册，不以小程序会员身份直接登录后台。
- 初始超级管理员在部署时安全创建；仅超级管理员可开通、停用运营账号。运营账号开通后可直接登录，不强制修改初始密码，保留主动改密入口。
- 运营忘记密码时由超级管理员重置密码，运营可直接使用该密码登录，自主选择是否修改；超级管理员忘记密码时由部署维护人员通过服务器恢复，不提供公开找回入口。重置密码立即使该账号已有会话失效。
- 停用运营账号立即使其已有会话失效，并阻止再次登录；历史操作记录保留。此停用不涉及小程序会员身份，也不产生禁用会员的能力。账号开通、重置密码和停用操作均留痕，记录不包含密码或会话令牌原文。
- 普通运营属于受信任的内部工作人员，与超级管理员一样可查看完整会员资料，包括未公开资源与需求、真实姓名、邮箱、绑定手机号，以及活动报名联系手机号和自定义答案；会员对其他会员的展示开关不限制此后台查看权限。活跃度导出仍限于下述约定字段。
- 两类角色均可直接下架、恢复活动或隐藏违规评论、点评，无需另行审批；必须填写原因，记录操作人、操作时间及对象，保留历史记录。首期不因此增加恢复已隐藏评价的能力。
- 会员列表可按编号、用户名称、真实姓名或手机号搜索，按邀请来源、资料完善情况和活跃情况筛选。会员详情可查看个人资料、邀请上下级关系及行为记录。
- 活跃度提供近 7 天、近 30 天视图，分别统计浏览活跃和参与活跃。近 30 天查看过活动属于浏览活跃；近 30 天报名、到场、发起活动、评论或点评属于参与活跃，到场单独统计。
- 入会满 30 天且连续 30 天没有参与行为属于长期未参与；其中区分仍在浏览与完全沉默。
- 活跃度可按行为、邀请来源、资料完善情况筛选；导出当前筛选结果时只包含会员编号、用户名称、行为次数、最近活跃时间，不含手机号、真实姓名和邮箱。
- 管理员首期无会员禁用、资料纠正、修改绑定手机号或修改邀请关系的权限。
- 管理员可查看所有活动的统计数据、报名联系手机号和自定义问题答案；签到只由各活动发起人标记，管理员不能代签到。
- 两类角色均可在后台维护小程序“活动”页运营文案和“助手”页运营文案；仅超级管理员可指定拥有小程序前端修改权限的会员，未获指定的会员不能修改。后台账号与会员的具体关联流程另行设计，不因拥有后台角色自动授权。当前客户“学加”的默认文案分别为「连接资产运营人才，共建共享“学加”学友生态」和「“学加”活动智能助手」。文案作为平台配置供两端读取，不改变 tab 名称。

**验收条件**

1. 后台用相同测试数据展示近 7 天、近 30 天两套统计；浏览活跃与参与活跃可分别识别。
2. 只浏览、从未参与的满 30 天会员可同时出现在“浏览活跃”和“长期未参与”中；完全沉默会员单独可筛出。
3. 搜索、筛选后的导出仅包含当前结果和约定字段，不混入私密资料。
4. 管理员可查看会员详情与邀请关系，但不能在后台修改会员资料、手机号、邀请关系或禁用会员。
5. 管理员可查看任一活动的统计、报名联系手机号和自定义答案；管理员尝试为报名者标记到场时被拒绝。
6. 后台修改两处运营文案后，小程序相应页面显示新文案；后台指定的平台管理员可从小程序前端修改并使两端读取到同一结果；普通会员提交同类修改被拒绝。
7. 超级管理员和普通运营均可通过账号密码登录；会员会话不能调用后台接口，后台会话不能冒充会员。普通运营不能开通、停用运营账号或指定小程序文案编辑权限。
8. 运营首次登录或被重置密码后可直接进入日常业务，不强制修改密码；保留主动修改密码入口。重置密码和停用账号后，该账号所有旧会话立即失效；停用账号不能重新登录，历史记录仍可追溯。
9. 普通运营可以查看会员未公开资料及敏感联系方式，但活跃度导出仍不包含手机号、真实姓名和邮箱。
10. 两类角色均可直接执行活动下架、恢复及违规评价隐藏；缺少原因时拒绝操作，成功后可追溯操作人、时间、对象及原因。

## 5. 权限与数据边界

| 数据或操作 | 浏览用户 | 已完善会员 | 本活动发起人 | 平台管理员 |
| --- | --- | --- | --- | --- |
| 活动详情、阅读与报名列表中的头像和名称 | 可 | 可 | 可 | 可 |
| 完整会员名片 | 不可 | 按主人展示设置 | 按主人展示设置 | 可查看 |
| 真实姓名、邮箱、绑定手机号 | 仅本人 | 仅主人在名片主动公开后可见 | 不因发起活动获得额外权限 | 可查看 |
| 本次报名联系手机号、自定义答案 | 仅本人 | 仅本人 | 仅自己活动 | 可查看所有活动 |
| 发布、报名、评论、点评 | 资料未完善时不可 | 可 | 可 | 后台身份不自动获得会员操作权 |
| 手动标记到场 | 不可 | 不可 | 仅自己活动 | 不可代签到 |
| 下架与恢复活动 | 不可 | 不可 | 不可 | 可 |
| 修改两处运营文案 | 不可 | 不可，除非被后台指定为平台管理员 | 不因发起活动获得权限 | 后台可修改；被指定者可在前端修改 |

上述“平台管理员”列同时适用于超级管理员和普通运营。仅超级管理员可以开通、停用运营账号、重置运营密码及指定小程序文案编辑权限；普通运营不可执行这些操作。两类角色均不得修改会员资料、绑定手机号或邀请关系、禁用会员或代发起人签到。

权限必须由服务端或统一业务层校验；隐藏按钮本身不算通过验收。

## 6. 运营指标与验收场景

首期记录而不预设业务目标值的指标：资料完善人数、活动浏览次数与人数、当前有效报名人数、报名转化率、到场人数、近 7/30 天浏览活跃和参与活跃人数、长期未参与人数、AI 推荐后的查看与报名。

端到端验收至少覆盖：

1. 分享者邀请码进入 → 新用户浏览 → 邀请关系固定 → 完善资料 → 报名 → 发起人看到当次联系手机号与答案。
2. 用户修改头像或名称 → 既有阅读和报名列表同步显示新值；修改本次报名联系手机号不影响绑定手机号。
3. 活动浏览、重复浏览、未识别浏览 → 阅读列表和浏览统计各按自己的口径变化。
4. 会员发活动 → 自定义问题 → 首次报名后锁定问题 → 截止前修改答案 → 活动前取消报名 → 发起人签到。
5. 管理员下架 → 旧分享入口显示下架状态 → 已报名者在小程序内可查看下架通知 → 管理员恢复后可查看恢复通知。
6. 后台按活跃类型和邀请来源筛选 → 查看会员详情 → 导出不含私密字段的结果。

这些是目标业务验收场景；当前实现及各层验证证据以[实现日志](../implementation-log/2026-09.md)为准，不能将本节场景或设计确认视为已完成验收。真实微信、真机与部署证据须分别核对。

## 7. 实施前仍需定细节

以下事项不改变已确认的产品方向，但需要在页面或技术设计时落成明确规则：

1. 【已确认】评论与点评的区别、输入与展示、本人修改删除、单人点评限制，以及管理员隐藏违规内容的规则，见 F06。
2. 【已确认】管理员可查看所有活动的统计、报名联系方式和自定义答案，不可代发起人签到，见 F08 和第 5 节。具体后台页面布局待设计。
3. 【已确认】取消报名后立即释放名额，并发报名不得超出人数上限；浏览人数为零时，报名转化率显示“—（暂无浏览）”，见 F03–F05。
4. 【已确认】活动恢复后不延长原定时间，报名能否继续按截止时间及名额判断；取消、下架与恢复只做小程序内通知，不做小程序外主动提醒，见 F03。具体页面入口待界面设计。
5. 账号主体与小程序真实配置由项目方负责；微信手机号、头像昵称、朋友圈参数和邀请绑定需要真机验收。官方文档级核验见需求草案第 6 节。
6. AI 服务的数据处理、资源与需求的存储及展示策略，以及推荐效果的试运行评估办法。
7. 【已确认】名片中头像、用户名称固定展示，其余七个字段首次默认关闭，由会员逐项开启，见 F02。
8. 【已确认】收费活动采用单一人民币固定金额，首个报名后锁定；报名立即成功并占用名额。平台不参与或记录收费、付款、退款与争议处理，只展示统一提示并由报名者通过活动咨询联系方式联系发起人，见 F03–F04。
9. 【已确认】后台两级角色、账号密码登录、账号发放与恢复、停用及会话失效、普通运营查看完整会员资料和直接管理违规内容，见 F08。后台账号与小程序会员的显式关联及小程序文案授权入口仍待设计，不阻塞独立后台登录。
