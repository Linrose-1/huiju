# 活动海报与双方式分享

确认日期：2026-11-05。属于老板新增优化，不复用原28项的编号。

## 原话与确认

老板原话：“有聚点发布活动及活动列表两个区域，最好能有个地方，能用AI生成一个相对格式化的海报。在‘分享’时，可以出现两种形式的分享：小程序直接分享、活动海报分享。分享的时候都带上用户邀请码。”

用户确认“AI提炼文案、使用已有封面、固定模板”，要求先看模板图片；已确认[海报模板v1](../资源/活动海报/海报模板-v1-已确认.png)。示意图中的时间、地点、费用及码为预览内容，不作为真实活动数据或正式可扫码资源。正式海报由确定性Canvas绘制，使用现有封面，不调用图片生成模型。

用户另行确认：仅发起人生成并确认文案；同一活动的其他分享者复用；每位发起人每天最多成功生成5次，与“AI发活动”独立；失败不扣；未生成文案仍可用标题、封面和基本信息分享。

2026-11-05 用户进一步确认实际Canvas导出的独立PNG图片预览（1500×2900），交付对象为海报图片，不是页面截图。该预览的码区为不可扫码的本地图标；图片效果确认不等于真实微信码、相册权限或转发验收。

## 产品规则与页面合同

- 活动列表卡片、活动详情分享按钮、发布后到达的活动管理页分享按钮，都进入“分享活动”页。原生菜单直接分享继续保留，草稿、取消或下架活动不生成海报。
- 分享页提供“小程序直接分享”和“活动海报分享”。直接分享目标是公开活动详情，不是管理页或海报编辑页；仅携带公开活动ID与当前分享者邀请码。
- 海报沿用已确认模板：米白底、深绿色品牌、活动邀请、完整标题、简短介绍、5:4现有封面、活动看点、时间地点费用、底部报名提示与真实专属小程序码。无封面用已有校园底图；品牌名称和显示状态跟随后台品牌设置。
- 分享时身份需已识别并取得本人邀请码，资料未完整的游客也可分享。AI生成及确认须本人发起且资料完整。服务端重新验证，不只隐藏按钮。
- 发起人可点击AI提炼、手动修改简介和两条亮点，再点“确认并使用”。候选不自动保存、不改活动原文；简介最多40字、看点最多两条，每条24字。可清空文案改用基本信息。其他分享者不能修改。
- 时间、地点、费用直接读取活动事实，不交由AI生成。AI只接收已发布活动标题和公开介绍，不附加手机号、报名答案、邀请码或会员资料。AI未配置或失败仍允许基本信息海报。
- AI候选需检查确认；已确认文案在标题、介绍、封面、起止时间、地点或费用变化后失效。过期文案不继续展示，基本信息仍取最新值，发起人可重新提炼/确认。
- 保存冲突保留输入；“重新读取已确认文案”在有未确认修改时先询问，不自动丢稿。生成/确认/导出锁定重复操作；切换身份或离页丢弃旧结果。
- 海报先生成预览，再保存相册或调用微信图片分享菜单；不支持该菜单的客户端提示保存后分享，不假装完成转发。生成失败不提供假码或无邀请码图片。
- 每张海报码绑定生成者；接收者转发已有图片仍属于原生成者，想使用自己的邀请来源须在小程序内重新生成。

## 接口与数据

| 接口 | 用途与权限 |
| --- | --- |
| GET `/api/v1/activities/:id/poster` | 已识别用户读活动事实、有效确认文案、sourceHash/version、本人能否编辑 |
| POST `/api/v1/organizer/activities/:id/poster-draft` | 发起人生成候选；返回独立剩余额度，不直接确认 |
| PUT `/api/v1/organizer/activities/:id/poster` | 发起人提交文案及sourceHash/version；旧活动事实或旧版本409 |
| POST `/api/v1/activities/:id/poster-code` | 生成当前身份专属码；不接受客户端指定邀请码 |
| GET `/api/v1/activity-posters/resolve/:scene` | 匿名解析公开活动ID及邀请码，无其他会员或管理数据 |

新增0019四表：`activity_poster_copies`、`activity_poster_shares`、`ai_poster_usages`、`ai_poster_reservations`。只新增表/FK/索引，不修改既有业务表。确认内容按活动版本保护；分享短码为p加24位随机十六进制，活动与分享者唯一，不设置短期失效时间。活动取消/下架后旧码停止解析；已保存图片无法撤回，扫码以服务端最新状态为准。

AI每日额度按北京时间成功完成日计算，独立于草拟额度；成员锁、短事务预留、事务外模型调用、完成时重检身份/活动指纹/额度、预留标识隔离；进程最多4个模型调用。微信码缓存最多100项/1小时，每用户15分钟30次请求、同用户最多一个及进程最多4个并发；这些进程限制不冒充跨实例全局限流。

App冷启动/外部进入先识别海报scene，解析并捕获邀请码后才允许静默身份建立。解析失败可重试，不在失败时以无来源创建新身份。普通分享来源及既有首次有效邀请关系规则不变。无上一页返回首页，内部进入沿原页面栈返回。
