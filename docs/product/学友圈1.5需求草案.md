# 有聚点｜1.5 学友圈需求草案

状态：用户已确认头脑风暴与六图 UI，并授权实现本稿已确认的首版核心规则；首版代码与工程验证完成，人工验收待进行。以下“待确认”扩展仍未冻结，不纳入实现。\
日期：2026-09-30\
依据：[版本路线图](版本路线图.md)、[首期 PRD](首期PRD.md)及本轮逐项确认。2.0 店友圈暂不讨论，也不纳入本草案。

## 一、目标与范围

学友圈让已完善资料的学友发布园区资源、运营资源、服务资源和门店帖子，并把帖子对外分享。外部访客完整浏览帖子后，可表达意向，在这一过程中加入有聚点成为新学友。园区资源包含出租、出售、转让、寻租、购买五类。

本版关注资源发布、发现、分享、意向联系和平台处置；不从“门店”一词推导商品商城、交易、贡献值或智米规则。

## 二、已确认的产品规则

1. 帖子发布后立即公开并可对外分享；平台事后下架处理，不设置普通帖子发布前审核。
2. 完成绑定手机号、主动设置头像和用户名称三项资料的学友可以发帖。普通学友也可以发布介绍他人门店的帖子；“门店官方”等身份标签及其核验办法尚未确认。
3. 发帖先选择类型，再填写通用信息和该类型少量专属信息；具体字段待逐类确定。
4. 外部访客可以完整浏览分享帖。点击“我感兴趣”时直接引导至微信授权登录及资料完善页；只有三项资料齐备后才能提交意向。
5. 完成登录和资料后返回原帖，保留此前的意向上下文，由用户再次确认才提交。登录成功、中途取消或资料尚未补齐不会自动提交意向。
6. 意向确认页明确展示可修改的联系电话；提交后仅该帖发布者可见。绑定手机号不会因为登录、浏览帖子而自动向发布者公开。
7. 发帖者与分享者可以不同。意向交给发帖者；新访客的邀请来源归实际分享者，沿用“首次有效来源固定”，已有学友的邀请关系不因再次打开分享帖而改变。
8. 平台下架后，旧分享链接仍可打开，但只显示下架状态，不展示资源详情或接受新意向；作者可查看下架原因，历史意向保留。作者可修改下架帖，但只有平台管理员复核后才能恢复公开。
9. 作者可主动将已完成的资源帖标为“已结束”。旧链接保留内容并显示结束状态，不再接收新意向；历史意向保留。“已结束”与平台“已下架”是不同状态。
10. 学友圈作为小程序第四个底部 Tab。首期已有“活动｜助手｜我的”三个入口保持原有职责；四个 Tab 的具体排列按页面实现确定。
11. 帖子可以不带图片，最多上传 6 张；浏览页展示作者实际上传的图片。
12. 各类帖子的最小字段按第五节字段表执行；运营资源与服务资源首版不增加专属必填项。

## 三、建议的最小业务链路（尚待整体验收）

已完善资料学友选择类型并发布帖子 → 任何访客从列表或分享链接浏览 → 访客点击“我感兴趣” → 未完善资料者进入现有登录/资料流程并返回原帖 → 用户核对联系电话并明确提交 → 发帖者接收意向 → 作者结束帖子或管理员按原因下架/恢复。

列表、意向列表和操作记录可能增长，须有服务端分页及加载、空结果、失败重试。服务端负责资料门槛、帖子归属、公开状态、联系方式可见范围和提交时状态重查；页面上的按钮显隐不能替代权限判定。

## 四、待确认：会改变实现的产品决定

1. 普通学友介绍他人门店时，帖子如何标明发帖人与门店的关系；是否存在“门店官方”以及如何核验。
2. 意向除了联系电话是否包含留言、具体需求；是否有处理状态或通知。
3. 作者主动结束后能否重新开放；作者修改普通公开帖子时是否需要留下变更痕迹。
4. 平台如何发现并处置问题帖子，例如后台巡查、用户举报；下架与恢复的管理员角色和通知对象。

## 五、已确认的最小发帖字段

| 帖子类型 | 必填 | 选填 | 展示口径 |
| --- | --- | --- | --- |
| 所有类型共用 | 类别、标题、正文 | 地点、图片 0—6 张 | 列表显示类别、标题、摘要、首图（有图时）；详情显示完整正文与全部图片 |
| 园区资源 | 子类：出租／出售／转让／寻租／购买 | 面积、报价或预算、有效期 | 价格只作为发帖者填写的信息，不生成平台交易、支付或结算状态 |
| 运营资源 | 无额外必填 | 无额外结构化字段 | 用标题和正文说明资源内容与合作需求 |
| 服务资源 | 无额外必填 | 无额外结构化字段 | 用标题和正文说明服务内容与适用对象 |
| 门店 | 门店名称 | 无额外结构化字段 | 普通学友也能介绍他人门店；不自动标为“门店官方” |

标题与正文不得只有空白字符；图片必须由上传者本人选择，发布时不接受任意外部图片地址。地点是发帖者自填的展示信息，不要求精确定位。面积、报价或预算、有效期均可留空，不用虚构的“面议”或“长期有效”替代未填写。字段长度、图片格式与大小按工程安全边界另定，不据此扩展业务字段。

五个页面的入口、跳转和状态见[学友圈页面流转草案](学友圈1.5页面流转草案.md)。

## 六、工程实现前的边界

- 已确认的第四个 Tab 已同步到小程序导航文档；其余待确认规则明确后再补 1.5 验收条件。本草案不修改首期 PRD 的既有验收范围。
- 新增帖子、意向与处置规则应有明确 API 模块和数据所有权，复用现有会员身份、首次邀请关系及后台会话能力，不把会员资料中的资源文字字段当作帖子数据库。
- 新 schema 只生成并审阅 Drizzle migration；执行到任何数据库须按目标另行核对与授权。
- 真实微信授权、分享、头像与手机号能力、微信开发者工具和真机验收须分别记录，不以模拟身份或工程检查冒充。

## 七、已确认链路的验收场景（实现后验证）

- 新访客经学友分享链接进入公开帖，可看完整内容；点击“我感兴趣”后进入登录/资料补全，返回同一帖子，意向尚未提交。
- 用户在确认页修改联系电话并明确提交后，发帖者可查看该次联系方式；普通浏览者、分享者及其他作者不能读取。中断登录或取消确认不产生意向。
- 发帖者与分享者不同，意向归发帖者；新用户邀请来源归分享者。已有邀请关系不被再次分享覆盖。
- 帖子被下架后，旧链接只显示下架状态；作者能看原因并编辑，不能自行恢复。作者主动结束后，旧链接仍可浏览正文但不能新提交意向；两种状态均保留历史意向。
- 公开列表、本人帖子和作者意向列表可逐页读取；追加失败保留已有内容，刷新后从第一页重新读取。

## 八、后台管理页面实现（2026-10-05）

后台新增“学友圈管理”入口（`/circle`），超级管理员与普通运营均可进入。沿用现有后台鉴权和学友圈管理接口，按类别服务端筛选，每页20条；列表展示发布者、类别、发布时间和公开中／已结束／已下架状态。详情展示正文、类别字段、下架原因及分页操作记录，下架／恢复必须填写1–1000字原因，重复提交期间锁定操作。

恢复只改变平台下架状态，不重新开放作者已结束的帖子，不删除历史意向。当前接口不提供后台标题搜索或状态筛选，页面不对单页数据做伪筛选；后台不增加作者编辑、代提交意向或意向联系方式读取能力。公开图片可预览；现有图片接口对下架图片有访问限制，本轮页面明确提示不可预览，未扩大图片权限。

本节记录实现范围，验证层级见[10月实现记录](../implementation-log/2026-10.md)；内存浏览器验收不等同于真实库处置或上线通过。
