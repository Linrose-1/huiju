# 身份与会话｜首个业务流程

状态：最小技术设计，2026-09-25。产品行为以[首期 PRD](../product/首期PRD.md) F01、F02 为准；本文件不表示微信账号能力或真实登录已经验证。

## 1. 两类主体

| 主体 | 身份来源 | 服务端主体键 | 用途 |
| --- | --- | --- | --- |
| 小程序会员 | `wx.login` 临时 code，由 API 向微信换取 `openid` | `member.id` | 浏览留痕、资料、邀请、活动与报名 |
| 后台管理员 | 后台登录凭据，具体发放与找回方式待确认 | `admin_account.id` | 后台查询、下架与恢复 |

管理员是否兼具小程序会员身份，由两条独立会话和显式授权关联决定；不能因为拥有后台会话就自动成为某位会员。小程序前端修改运营文案时，API 仍需验证该会员是否被后台指定。`unionid` 若微信返回，可作为辅助关联信息，不能替代当前小程序的 `app_id + openid` 唯一键。

## 2. 小程序建立会话

1. 页面可先匿名展示公开活动；分享入口暂存活动标识和邀请码。匿名访问不创建会员，也不绑定邀请。
2. 小程序调用 `wx.login`，将一次性 code 和本次入口邀请码提交给 `POST /api/v1/auth/wechat/session`。前端不持有 AppSecret。
3. API 调用微信 `code2Session`，校验结果；按 `app_id + openid` 唯一键查询会员。已有会员直接建立新会话，不修改原邀请关系。
4. 首次识别成功时，在同一数据库事务中创建会员、微信身份映射和邀请关系。邀请码指向有效会员时绑定该会员；无有效来源时绑定平台根节点。唯一键冲突时读取已经创建的会员，不重复创建、不覆盖邀请关系。
5. API 返回随机不可猜测的会话令牌及到期时间；数据库只保存令牌摘要、主体、到期与撤销时间。小程序后续请求在 `Authorization: Bearer` 中携带令牌。
6. 会话过期或撤销时返回明确的未认证错误；小程序重新走 `wx.login`。用户主动退出时撤销当前会话。

邀请码合法性检查、平台根节点回退和首次绑定必须在服务端完成。朋友圈单页模式只有在成功建立平台身份后才绑定；具体进入链路需真机验证。登录失败时仍可匿名浏览，但不能使用需要识别身份的操作。

## 3. 后台会话

后台使用独立的 `admin_account` 与服务端会话。登录凭据只经 HTTPS 提交，后台会话令牌以 `HttpOnly`、`Secure` Cookie 交付；对有状态修改的接口实施同源校验与 CSRF 防护。登出、过期和后台撤销均使服务端会话失效。具体初始管理员创建、密码或其他登录方式、找回流程，列为实施前待确认项，不在本设计中假定微信会员身份即可登录后台。

## 4. 资料门槛与敏感信息

`profile_complete` 不依赖客户端传值，而是服务端按“已绑定手机号 + 用户主动设置头像 + 用户主动设置名称”实时判断；默认头像和“用户编号”名称不算完成。资料未完成仍可凭会话浏览和维护本人资料，不能报名、发布、评论或点评。

微信手机号只能由用户主动授权后由 API 按微信凭证取得并绑定；首期不开放本人修改已绑定手机号的接口。报名联系手机号独立保存于报名记录，不反写会员绑定手机号。会话日志不记录微信 code、令牌、手机号或 AppSecret 原文；令牌摘要与个人资料设置不同访问权限。有效期、密钥轮换和并发会话数量在实现前落到配置及测试，不硬编码在产品规则中。

## 5. 最小接口契约

| 接口 | 作用 | 主要校验 |
| --- | --- | --- |
| `POST /auth/wechat/session` | 以微信 code 建立或恢复会员会话并处理首次邀请 | code 一次性、`app_id + openid` 唯一、邀请不覆盖 |
| `GET /auth/session` | 返回当前主体、资料完成状态和可用能力 | 会话有效；只返回必要字段 |
| `DELETE /auth/session` | 撤销当前会话 | 当前令牌摘要匹配 |
| `POST /members/me/phone` | 经微信授权绑定本人手机号 | 会员会话、尚未绑定、凭证有效 |
| `PATCH /members/me/profile` | 更新本人可编辑资料 | 会员会话、字段白名单；不可修改绑定手机号或邀请关系 |

接口均挂在全局 `/api/v1` 前缀下。后台登录接口和凭据格式在登录方式确认后补充。匿名活动详情单独走公开接口；无需伪造匿名会员会话。

## 6. 客户端环境与会话生命周期（实现约束）

API 地址由各端服务层集中配置，不在页面散落地址；凭据和用户缓存必须与实际 API 环境绑定。环境切换、退出或账号变化后清理当前会话上下文，旧请求返回时不能写回原用户或令牌。并发会话恢复应合并同一次请求，同时核对请求发起时的环境与会话是否仍有效，避免迟到结果恢复已退出身份。

公开浏览不依赖会话完成；身份相关请求等待识别成功后再发送。缓存只能改善展示，不能代替服务端鉴权或最新资料门槛。具体存储 key、请求取消与并发实现随登录切片落地；当前尚未实现客户端认证层。验收覆盖冷启动、分享直达、过期会话、环境切换和迟到请求，见[验证清单](../testing/README.md)。
