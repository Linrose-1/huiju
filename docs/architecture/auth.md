# 身份与会话｜首个业务流程

状态：最小技术设计，2026-09-28 更新后台账号规则。产品行为以[首期 PRD](../product/首期PRD.md) F01、F02、F08 为准；本文件不表示微信账号能力或真实登录已经验证。

## 1. 两类主体

| 主体 | 身份来源 | 服务端主体键 | 用途 |
| --- | --- | --- | --- |
| 小程序会员 | `wx.login` 临时 code，由 API 向微信换取 `openid` | `member.id` | 浏览留痕、资料、邀请、活动与报名 |
| 后台管理员 | 独立账号与密码；角色为 `super_admin` 或 `operator` | `admin_account.id` | 后台查询、内容管理及按角色管理运营账号 |

管理员是否兼具小程序会员身份，由两条独立会话和显式授权关联决定；不能因为拥有后台会话就自动成为某位会员。小程序前端修改运营文案时，API 仍需验证该会员是否被后台指定。`unionid` 若微信返回，可作为辅助关联信息，不能替代当前小程序的 `app_id + openid` 唯一键。

## 2. 小程序建立会话

1. 页面可先匿名展示公开活动；分享入口暂存活动标识和邀请码。匿名访问不创建会员，也不绑定邀请。
2. 小程序调用 `wx.login`，将一次性 code 和本次入口邀请码提交给 `POST /api/v1/auth/wechat/session`。前端不持有 AppSecret。
3. API 调用微信 `code2Session`，校验结果；按 `app_id + openid` 唯一键查询会员。已有会员直接建立新会话，不修改原邀请关系。
4. 首次识别成功时，在同一数据库事务中创建会员、微信身份映射和邀请关系。邀请码指向有效会员时绑定该会员；无有效来源时绑定平台根节点。唯一键冲突时读取已经创建的会员，不重复创建、不覆盖邀请关系。
5. API 返回随机不可猜测的会话令牌及到期时间；数据库只保存令牌摘要、主体、到期与撤销时间。小程序后续请求在 `Authorization: Bearer` 中携带令牌。
6. 会话过期或撤销时返回明确的未认证错误；小程序重新走 `wx.login`。用户主动退出时撤销当前会话。

邀请码合法性检查、平台根节点回退和首次绑定必须在服务端完成。朋友圈单页模式只有在成功建立平台身份后才绑定；具体进入链路需真机验证。登录失败时仍可匿名浏览，但不能使用需要识别身份的操作。

## 3. 后台会话

后台使用独立的 `admin_account` 与服务端会话，以账号和密码登录，不开放注册。角色为超级管理员（`super_admin`）和普通运营（`operator`）；不假定微信会员身份即可登录后台。登录凭据只经 HTTPS 提交，后台会话令牌以 `HttpOnly`、`Secure` Cookie 交付；对有状态修改的接口实施同源校验与 CSRF 防护。登出、过期和后台撤销均使服务端会话失效。

- 初始超级管理员由部署维护人员在部署时安全创建；不使用仓库内固定初始密码或默认公开账号。仅超级管理员可以开通、停用运营账号和重置运营密码。
- 运营账号开通或密码重置后可直接登录，不强制修改密码；后台保留本人主动修改密码入口。
- 超级管理员忘记密码时由部署维护人员通过服务器恢复，不增加公开找回接口。任何密码重置都立即撤销该账号全部已有会话；停用运营账号也立即撤销全部会话并拒绝后续登录。
- 账号开通、密码重置与账号停用保留审计记录，不删除原操作历史，不记录明文密码或会话令牌。后台账号停用不影响其可能持有的小程序会员身份。
- 口令只保存安全散列，会话只保存令牌摘要。受限请求实时核对账号状态及会话是否撤销，不能仅依赖客户端缓存角色或登录时的状态。

实现约束：复用 `admin_accounts`、`admin_sessions`，通过一对一的 `admin_credentials` 保存登录账号、密码散列、角色及失败限制状态；历史强制改密字段保留兼容但不再作为访问门槛，账号审计单独记录于 `admin_account_audit`。本人改密与管理员重置密码均撤销全部已有会话；本人改密成功后需要重新登录。`ADMIN_ORIGIN` 必须配置为绝对 origin，生产环境使用 HTTPS 及 `Secure`、`HttpOnly`、`SameSite=Strict` Cookie；仅非生产环境显式设置 `ADMIN_ALLOW_LOCAL_HTTP=true` 时允许 loopback HTTP 开发联调，不能将该例外用于对外部署。

后台与会员的显式关联、小程序文案编辑授权入口仍待设计，本轮不提供关联能力；这不阻塞独立后台登录。本轮最小范围为后台登录、运营账号管理与评论／点评隐藏；上述设计不代表已创建部署账号或完成外部验收。

## 4. 资料门槛与敏感信息

`profile_complete` 不依赖客户端传值，而是服务端按“已绑定手机号 + 用户主动设置头像 + 用户主动设置名称”实时判断；默认头像和“用户编号”名称不算完成。资料未完成仍可凭会话浏览和维护本人资料，不能报名、发布、评论或点评。

微信手机号只能由用户主动授权后由 API 按微信凭证取得并绑定；首期不开放本人修改已绑定手机号的接口。报名联系手机号独立保存于报名记录，不反写会员绑定手机号。会话日志不记录微信 code、令牌、手机号或 AppSecret 原文；令牌摘要与个人资料设置不同访问权限。有效期、密钥轮换和并发会话数量在实现前落到配置及测试，不硬编码在产品规则中。

## 5. 最小接口契约

| 接口 | 作用 | 主要校验 |
| --- | --- | --- |
| `POST /auth/wechat/session` | 以微信 code 建立或恢复会员会话并处理首次邀请 | code 一次性、`app_id + openid` 唯一、邀请不覆盖 |
| `GET /auth/session` | 返回当前主体、资料完成状态和可用能力 | 会话有效；只返回必要字段 |
| `DELETE /auth/session` | 撤销当前会话 | 当前令牌摘要匹配 |
| `POST /members/me/phone` | 经微信授权绑定本人手机号 | 会员会话、尚未绑定、凭证有效 |
| `PATCH /members/me/profile` | 更新本人可编辑资料 | 会员会话、字段白名单；不可修改绑定手机号或邀请关系 |

接口均挂在全局 `/api/v1` 前缀下。后台采用已确认的账号密码登录，具体接口以[接口文档](../api/README.md)及 OpenAPI 契约为准；必须独立于上表会员会话。匿名活动详情单独走公开接口；无需伪造匿名会员会话。

## 6. 客户端环境与会话生命周期（实现约束）

API 地址由各端服务层集中配置，不在页面散落地址；凭据和用户缓存必须与实际 API 环境绑定。环境切换、退出或账号变化后清理当前会话上下文，旧请求返回时不能写回原用户或令牌。并发会话恢复应合并同一次请求，同时核对请求发起时的环境与会话是否仍有效，避免迟到结果恢复已退出身份。

公开浏览不依赖会话完成；身份相关请求等待识别成功后再发送。缓存只能改善展示，不能代替服务端鉴权或最新资料门槛。2026-09-26 已实现 API 环境绑定的缓存、并发登录合并和 epoch 迟到响应防护；隔离测试覆盖冷启动、邀请捕获、过期会话、环境切换和迟到请求，真实微信验收仍未完成，见[验证清单](../testing/README.md)。

## 7. 本次实现配置

2026-09-27用户另行确认本地模拟验收：客户尚未申请正式小程序时，使用独立开发脚本替换微信适配器，固定模拟身份、手机号；不修改真实微信会员。脚本只接受本机127.0.0.1:3306/huiju并绑定127.0.0.1:3001，测试身份使用独立appId命名空间，测试会话使用独立摘要域，与正常API令牌不互通。业务资料门槛和报名服务仍执行原有规则，测试资料及报名留在本机开发库；不是数据库物理隔离。正常API不导入测试适配器，小程序正式构建不启用模拟入口，测试模式构建显式拒绝。操作方式见[工程脚本](../../scripts/README.md)。本例外仅用于明确标记的本地测试，不能计作真实微信授权或扩大为产品免授权规则。

会话有效期由 `MEMBER_SESSION_TTL_SECONDS` 配置（默认 604800 秒，允许 60–2592000）；同会员有效会话上限由 `MEMBER_SESSION_MAX_ACTIVE` 配置（默认 5，允许 1–20），登录在会员行锁内撤销超额旧会话。数据库仅保存令牌 SHA-256 摘要；微信会话密钥不返回小程序。

头像按本次用户确认存本机，由 `POST /members/me/avatar` 接收不超过 2 MiB 的 PNG/JPEG，并从受控头像目录提供读取。保存前使用 sharp 核对真实格式与声明 MIME 一致，并完整解码像素；总像素数不得超过 16,777,216，损坏或超限图片返回 `INVALID_IMAGE`，不写文件或更新资料完成标记。目录默认 `apps/api` 启动目录下 `.local-uploads/avatars`，可通过 `LOCAL_AVATAR_DIRECTORY` 指定；运行文件被忽略，不进入仓库。该接口与手机号授权都只更新本人；手机号重复绑定被拒绝。微信端资料保存使用 `POST /members/me/profile` 别名，和 PATCH 共用 DTO 与校验。
