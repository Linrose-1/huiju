# 权限策略｜首个业务流程

状态：权限设计，2026-09-28 更新后台两级角色。当前实现与验证证据见[实现日志](../implementation-log/2026-09.md)；本文件定义服务端约束，不以设计确认代替实现或验收。产品范围与展示规则以[首期 PRD](../product/首期PRD.md) F01–F08、第 5 节为准。

2026-10-19 已确认规则更新（实现待验证）：全新及三项资料未完整者均为游客；手机号绑定、主动头像与主动名称完整后才是会员。静默识别可建立游客会话，游客可浏览，业务操作时才补全；原 AI 找活动的仅会话例外撤销。内部 `requireMember` 等历史命名不等同于产品会员资格。

## 1. 服务端判定顺序

每个受限请求依次校验：会话有效 → 主体类型 → 所需资料完整度 → 资源归属或管理员能力 → 资源当前状态及时间 → 输入与并发约束。Guard 负责会话和主体类型；应用服务在同一事务内重新读取会影响写入资格的资源状态。前端可隐藏入口和显示补全引导，但服务端始终独立裁决。

发起人是 `activity.organizer_member_id` 指向的会员，不是永久角色。后台管理员是独立 `admin_account`，不是“所有活动的发起人”。运营文案的小程序编辑能力是后台授予某个会员的独立能力，不能由普通资料字段或前端传参取得。

后台请求还必须核对账号未停用、会话未撤销。超级管理员为 `super_admin`，普通运营为 `operator`；停用账号或重置密码立即使该账号全部旧会话失效。首次登录或密码重置后不强制改密，可按角色直接使用后台。

## 2. 最小操作矩阵

| --- | --- | --- | --- | --- |
| 浏览公开活动、公开阅读与报名名单的头像名称 | 可 | 可 | 可 | 可 |
| 查看报名名单的公开答案 | 不可 | 仅本活动有效报名者，且仅开启公开的非联系方式字段 | 未报名时无额外公开权限；管理名单权限不变 | 后台身份不自动获得会员接口权限 |
| 查看完整会员名片 | 不可 | 按主人逐字段设置 | 同普通会员 | 后台可查看 |
| 查看我的学友及本人至目标学友链路 | 不可 | 仅本人端点，头像名称摘要，排除平台根连接 | 同普通会员 | 后台身份不自动获得会员接口权限 |
| 活动特邀码管理/使用 | 不可 | 仅核验和使用本账号绑定手机号的码 | 仅管理自己活动的码及脱敏手机号 | 不自动获得代发权限 |
| 修改本人资料与名片设置 | 已识别游客可主动完善本人 | 本人 | 本人 | 不可代改 |
| 查看他人真实姓名、邮箱、绑定手机号 | 不可 | 仅主人主动公开的名片字段 | 无额外权限 | 后台可查看 |

| 查看活动咨询联系方式 | 不可 | 仅曾成功报名的活动 | 自己发起的活动 | 可查看 |
| 修改活动问题、查看本活动报名联系方式与答案、标记到场、开始前取消活动 | 不可 | 仅自己的活动 | 可 | 可查看所有报名详情，不可代签到或代取消 |
| 下架、恢复活动 | 不可 | 不可 | 不可 | 可 |
| 隐藏违规评论或点评 | 不可 | 不可 | 不可 | 可，填写原因并留痕 |
| 修改两处运营文案 | 不可 | 获后台指定的会员可从小程序修改 | 不因发起人身份获得 | 后台可修改 |

公开名单仅返回名片定位用 memberId、当前会员头像和名称，不返回 `member.phone`、`registration.contact_phone`、活动咨询联系方式或答案。完整名片由服务端按访问者与主人关系逐字段组装：头像、名称固定；其余七项默认关闭。主人和后台管理员的私有查看权限与普通名片展示权限分开实现。发起人看到报名联系方式，不因此看到报名会员未公开的绑定手机号。活动咨询联系方式由活动单独保存；本人取消报名、活动取消或下架后，曾成功报名者仍有查看权。

### 后台角色矩阵

| 操作 / 数据 | 超级管理员 `super_admin` | 普通运营 `operator` |
| --- | --- | --- |
| 查看完整会员资料、邀请关系和活跃度 | 可 | 可 |
| 查看未公开资源与需求、真实姓名、邮箱和绑定手机号 | 可 | 可 |
| 查看所有活动统计、报名联系方式和自定义答案 | 可 | 可 |
| 活跃度导出 | 仅会员编号、用户名称、行为次数、最近活跃时间 | 同左 |
| 下架、恢复活动；隐藏违规评论或点评 | 可，必须填写原因并记录操作人、时间和对象 | 可直接执行，无需超管审批，同样留痕 |
| 后台修改两处运营文案 | 可 | 可 |
| 开通、停用运营账号，重置运营密码 | 可 | 不可 |
| 指定小程序文案编辑权限 | 可 | 不可 |
| 修改会员资料、绑定手机号或邀请关系，禁用会员，代发起人签到 | 不可 | 不可 |

普通运营是受信任的内部工作人员；其后台查看权限不受会员对其他会员的名片展示开关限制。该权限不能放宽公开名片接口，导出不包含手机号、真实姓名或邮箱。隐藏违规评价必须保留内容和操作记录，不增加恢复已隐藏评价的能力。

历史最小范围为“后台登录 → 运营账号管理 → 评论／点评隐藏”。2026-09-30 已有会员查询实现，本轮新增两类后台角色均可使用的活动下架/恢复入口；每次写入通过 AdminService 校验 Cookie、账号启用状态、会话、Origin 和 CSRF，再调用活动领域服务。活动模块锁定活动行并原子保存状态、原因、操作者与通知。会员 Bearer 不能调用，草稿不可处置，不能代签到或代取消，恢复不改变原活动状态和报名窗口。新链路的 L1 与未完成真实验收见实现日志；2026-10-04活跃度、后台活动数据与运营文案权限已接入代码，数据库启用及实际验收另见实现日志。

## 3. 策略接口

建议在 API 应用层集中提供 `requireMember`、`requireCompleteProfile`、`requireOrganizer(activityId)`、`requireAdmin` 和 `canViewMemberField(viewer, owner, field)` 等判定入口。它们不是绕过数据库重读的缓存许可。活动下架或取消后，报名、评论、点评等写入须由业务服务再次校验当前状态。

拒绝操作时返回稳定的业务错误码，例如 `SESSION_REQUIRED`、`PROFILE_INCOMPLETE`、`FORBIDDEN`、`ACTIVITY_UNAVAILABLE`、`REGISTRATION_CLOSED`、`CAPACITY_FULL`。对用户的文案可以说明补全、截止、报满等原因；响应不包含未授权资料或数据库细节。

## 4. 待确认边界

后台管理员的初始建立、账号密码登录、运营账号发放与恢复、停用及会话失效规则已经确认，见[身份与会话](auth.md)。2026-10-04文案授权直接关联会员，不要求后台账号关联；超级管理员管理授权、普通运营不能授予或撤销。会员保存每次核对授权，撤销和保存锁定同一记录。收费活动没有平台付款状态；任何角色都不能从本权限矩阵推断报名者已经付款、应退款或完成费用争议处理。


2026-09-27实现补充（历史记录）：本人六项补充资料与七项展示设置接口、完整资料会员的公开名片接口已实现，复用现有member/member_visibility表，无新迁移。未选择字段由服务端省略，即使名片主人自己打开公开名片也不例外；私有资料只通过本人接口读取。当时后台权限尚为设计约束；后续实现状态见实现日志。

## 2026-10-28 微信信息与个性标注扩展

名片自主展示扩展为十项，新增微信号、二维码与个性标注分别控制，默认关闭（已获用户确认）。资料本人可编辑，不改变手机号/头像/名称完整度门槛、首次邀请关系或管理员能力。二维码不仅在名片JSON中过滤，二进制读取也校验会话、完整度与主人公开开关；本人上传管理不受自身公开开关限制。关闭后不提供新读取，但无法撤回对方先前已合法保存的图片。
## 2026-10-28 广告维护权限

第18、26项沿用现有后台内容维护角色：有效超级管理员及普通运营可维护广告、介绍和我的背景；写操作核对账号状态、Cookie会话、Origin及CSRF，操作留审计并使用版本冲突保护。小程序会员Bearer不授予后台权限。

已上架有效介绍与广告可匿名读取，其中联系字段是管理员主动发布的商务联系方式，不联查会员私人字段。原始上传图片只供管理员鉴权重裁，公开端只读取展示图片；介绍下架后公开详情不可访问，关联广告不再进入公开列表。当前目标和实际验收分别见PRD与实现日志。
