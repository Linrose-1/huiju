# 学友圈 1.5 核心实现

以已确认的需求和六张 UI 设计为范围：四类帖子、园区五子类、0–6 张本人图片、公开浏览与作者管理、明确意向、结束及后台处置；不扩展留言通知、重开、官方身份和举报。

## 数据所有权及状态

CircleModule 拥有 circle_posts、circle_images、circle_post_images、circle_intents、circle_operations 五表。复用 IdentityModule 的会话与三项完整资料门槛、AdminService 的 Cookie/Origin/CSRF。下架和结束为独立状态轴；编辑下架帖子保留下架状态，管理员恢复不改变已结束状态。普通已结束帖子首版不再编辑或重开。

发帖和意向写入在事务中重查当前会员资料；帖子状态修改、意向、处置以帖子行锁排序。同作者发帖重试按 author/requestId 唯一约束，意向重试按 post/member/requestId 唯一约束。requestId 是技术重试标识；不同新确认不据此推定产品层的“每人仅一次”。确认电话为独立快照，不修改或自动公开绑定电话。

## 图片和响应权限

图片仅接受本人选择的 PNG/JPEG，单张 2MiB、解码像素不超过 4096×4096；复用真实解码校验，存于 LOCAL_CIRCLE_DIRECTORY 或 .local-uploads/circle，数据库记录上传者及文件名。提交的 imageIds 须全部属于作者，拒绝任意外部 URL。没有公开帖子引用的图片仅上传者持会话可读；下架帖的图片无其他公开引用时匿名请求返回404。正文和电话不输出在公共错误中。

公开列表过滤下架；结束帖子仍展示内容。下架公开详情只返回受限视图，移除正文、位置、作者、图片和原因。作者 manage/mine 和 intents 分别校验归属；只有作者 intents 返回确认电话。所有接口使用 no-store，前端仍需在下架结果后清除已载入数据。
