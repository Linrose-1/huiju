# 首个业务流程：活动与报名状态

状态：最小技术设计，2026-09-26。依据[首期 PRD](../product/首期PRD.md) F01–F04。本次已实现身份、资料、活动浏览、报名、答案修改及本人取消接口，并通过隔离工程测试和真实 MySQL 单事务回滚测试。发布、活动取消/下架管理、签到、通知仍不在本次实现范围；以下完整状态设计不能一概当作已实现。本机MySQL多连接并发测试已通过，真实微信及完整人工验收仍待完成，证据见[实现日志](../implementation-log/2026-09.md)。

## 1. 流程入口

分享活动 → 匿名查看 → 微信身份识别并固定首次邀请 → 补齐手机号、头像、名称 → 会员发布活动 → 其他会员报名 → 发起人查看报名并标记到场。管理员可下架、恢复活动；发起人可在开始前取消活动。免费和收费活动共用同一报名流程；收费活动只增加固定金额和统一提示，平台不记录或处理付款与退款。

## 2. 活动状态分为两条轴

| 状态轴 | 值 | 变化与含义 |
| --- | --- | --- |
| 业务生命周期 `lifecycle` | `draft` → `published` → `cancelled` | 草稿不公开；发布无需平台审核；只有发起人可在活动开始前填写原因取消；取消为终态，首期无恢复取消流程 |
| 平台处置 `moderation` | `normal` ⇄ `removed` | 管理员填写原因下架或恢复；下架不删除活动、报名和原生命周期；恢复回到原生命周期，不改时间、名额或报名记录 |

报名截止和活动结束均由时间计算，不保存为可手动切换的活动状态。公开列表只展示 `published + normal` 的活动；旧链接命中 `removed` 时显示下架状态。`cancelled + normal` 的旧链接显示取消原因；若取消与下架并存，对普通访问者先展示下架状态，管理员仍可看到两条轴和操作记录。

| 动作 | 允许条件 | 原子结果 |
| --- | --- | --- |
| 发布 | 发起人资料完整，活动必填信息合法，生命周期为 `draft` | `published`；不经过管理员审核 |
| 发起人取消 | 本人发起、`published`、当前时间早于开始时间、原因非空 | `cancelled`，原子保存取消时报名人数快照并保留报名与操作记录；已报名者可查小程序内通知，答案永久锁定 |
| 管理员下架 | 管理员、非草稿且当前为 `normal`、原因非空 | `removed`，保留生命周期和报名；停止新增报名与评论，通知已报名者 |
| 管理员恢复 | 管理员、当前为 `removed`、原因非空 | `normal`；仅恢复原活动展示与原报名窗口，不延长时间或重置名额 |

管理员下架和发起人取消同一活动时，持有活动行锁后顺序执行，各自只修改所属状态轴。通知与状态变更应在同一业务事务中持久化，防止状态已改变而通知丢失；通知发送方式在通知模块实现时决定。

## 3. 报名开放条件

每次新报名在服务端事务内按当前数据库状态计算：

```text
会员会话有效且三项资料完整
AND activity.lifecycle = published
AND activity.moderation = normal
AND 当前时间 < min(报名截止时间或活动开始时间, 活动开始时间)
AND (未设人数上限 OR 当前有效占位数 < 人数上限)
```

报名截止时间不能晚于活动开始时间；若未填写，默认以开始时间为截止。具体页面上展示“已截止”“已报满”“已下架”等原因，API 使用稳定业务码。免费与收费模式不改变上面的时间、名额和身份判断。收费活动提交后同样立即报名成功并占位；平台不等待付款、不记录付款状态，也不据此改变报名资格。

## 4. 报名状态转换

| 原状态 | 动作与条件 | 新状态 | 名额变化 |
| --- | --- | --- | --- |
| 无报名 | 本人提交、满足开放条件、必填答案合格 | `active` | +1 |
| `active` | 本人于报名截止前修改答案，活动正常且未下架 | `active` | 0 |
| `active` | 本人于活动开始前取消 | `cancelled` | -1 |
| `cancelled` | 本人重新提交，重新满足报名开放条件并确认联系方式与答案 | `active` | +1，重新竞争当前名额 |

同一活动同一会员最多一条报名主记录；`active` 是会员未主动取消的报名，`cancelled` 保留本人取消历史。报名联系手机号是本次提交快照；再次报名时重新确认。展示名单的头像、名称实时读取会员当前资料。活动被取消或下架后，历史报名保留供本人、发起人和管理员按权限查看；新增报名被拒绝。活动取消不会把所有 `active` 报名改成 `cancelled`；取消事务把当时人数写入不可变快照，页面据此展示“活动已取消，取消前已有 X 人报名”，这些记录不计作实际到场。

第一笔报名成功即永久锁定该活动的问题、选项和收费金额，取消该报名也不解锁。用户修改答案的截止时点与取消报名的截止时点不同：前者是报名截止，后者是活动开始。活动取消后答案永久锁定；活动下架期间暂时锁定，恢复后仅在原报名截止前重新允许修改。发起人标记到场需本人活动及有效报名，签到记录与报名状态分开；管理员不能代签到。

## 5. 收费与活动咨询联系方式

- 收费活动设置一个大于 0 的人民币固定金额，数据库按分保存；所有报名者价格相同，首个报名后金额锁定。
- 平台不保存付款说明、收款码、付款状态或退款状态，不参与收费、收款、核验、退款和费用争议。活动或报名取消只改变业务状态及名额，页面统一提示联系发起人处理费用。
- 免费和收费活动都必须填写一段自由文本形式的活动咨询联系方式。公开详情不返回该字段；发起人、平台管理员及曾成功报名的会员可以查看。
- 本人取消报名、活动取消或活动下架后，曾成功报名者继续拥有查看权。发起人在活动结束前可以修改联系方式；有权者读取最新内容，当前有效报名者收到站内通知，修改写入操作记录。

## 6. 最小接口切面

接口均使用 `/api/v1` 前缀。下表固定首个免费及收费活动流程必需的动作与服务端责任；请求字段、响应 DTO 和 OpenAPI 文档在实现时与同一切片提交。

| 接口 | 主体与服务端责任 |
| --- | --- |
| `GET /activities/:id` | 匿名可读公开内容；活动咨询联系方式只按发起人、管理员或历史报名关系返回；按下架、取消状态过滤其他字段 |
| `POST /activities`、`PATCH /activities/:id`、`POST /activities/:id/publish` | 资料完整会员建立草稿；只有发起人可编辑并发布，发布前校验必填字段、咨询联系方式、时间及收费金额；首个报名后金额不可改 |
| `PUT /activities/:id/questions` | 仅发起人；锁活动行并确认从未出现报名 |
| `POST /activities/:id/registrations` | 资料完整会员；事务内校验开放窗口、问题答案、唯一报名及名额 |
| `PATCH /activities/:id/registrations/me`、`POST /activities/:id/registrations/me/cancel` | 本人；分别按报名截止和活动开始时间裁决，取消事务内释放名额 |
| `GET /activities/:id/registrations` | 公开只给头像名称；发起人可取本活动联系方式与答案；后台管理员按后台接口查看 |
| `POST /activities/:id/cancel` | 仅发起人且开始前；原因、状态、操作记录与站内通知原子持久化 |
| `POST /admin/activities/:id/remove`、`POST /admin/activities/:id/restore` | 后台管理员；原因、状态、操作记录与站内通知原子持久化 |

发起人签到可在报名切片后以独立动作加入，不借用管理员接口。客户端重试报名、取消和状态动作时，服务端通过唯一键、当前状态及必要的请求幂等标识避免重复占位、重复释放或重复通知。

## 7. 已确认的特殊状态规则

1. 取消报名后可以再次报名，但必须重新满足状态、时间、资料和容量条件，并恢复同一条主记录重新竞争名额。
2. 活动取消后保留原报名状态和名单，以取消事务保存的人数快照展示“取消前报名人数”；不批量改成会员主动取消，也不计作实际到场。
3. 活动取消后答案永久锁定；下架期间暂时锁定，恢复且仍在原截止时间前才重新允许修改。
4. 曾成功报名者永久保留本活动咨询联系方式的查看权；发起人修改时读取最新内容。
5. 收费活动与付款没有平台状态关联；费用问题只提示报名者联系发起人。

## 8. 实现切片的最小验收场景

- 同一微信身份并发首次登录，只生成一名会员和一条固定邀请关系；后续从其他邀请码进入不改上级。
- 未完成三项资料的会员不能发布或报名；仅默认头像和编号名称不算完成。
- 两人争抢最后一个名额时仅一人报名成功；重复提交不增加占位。报名者开始前取消后，名额立即可供他人在截止前报名。
- 取消者再次报名时重新竞争容量并复用原报名主记录；操作历史能区分首次报名、取消和再次报名。
- 第一笔报名与发起人修改问题并发时，以活动行锁顺序为准；报名成功后即使取消，问题仍不可改。
- 管理员下架后旧链接无法新报名；恢复后只在原报名窗口内重新开放。发起人开始前取消后保留原因、报名记录和站内通知。
- 活动取消后显示取消前报名人数并锁定答案；下架恢复后，未截止的原报名者可以继续修改答案。
- 收费活动报名立即占位且没有付款状态；从未报名者取不到咨询联系方式，历史报名者在取消或下架后仍能读取最新值。
- 公开名单仅返回会员当前头像和名称；报名联系手机号及答案只供本人、发起人和后台管理员按各自权限读取。
