# 小程序协作规则

本目录继承仓库根目录 `AGENTS.md`，并补充 uni-app 微信小程序约束。

## 技术与目录

- 使用 Vue 3、TypeScript、Vite、Pinia 和 uni-app，兼容 HBuilderX 工程习惯。
- 页面注册、分包和原生导航栏标题统一由 `src/pages.json` 管理；页面内容不重复渲染同名大标题。
- 页面以本次确认的设计稿和反馈为准；参考项目的视觉风格、类名前缀、组件尺寸不自动成为会聚规范。平台兼容以实际微信编译和设备结果为准，不用 H5 表现推断。
- 页面只负责展示和交互编排。网络访问集中到 `src/services/api`，微信登录、分享、手机号等能力集中到 `src/services/wechat`。
- 通用视觉组件放 `components/base`，带明确业务语义的组件放 `components/business`。
- Pinia 保存会话和必要的跨页 UI 状态；服务端业务数据不能因写入 store 就被视为最新事实。

## 边界与安全

- 小程序不得直连数据库、模型供应商或保存任何服务端密钥。
- 所有权限和资料完整度仍由 API 校验；前端路由拦截和按钮显隐只改善体验。
- 使用微信专属能力前，先核对 AppID、主体资质、基础库、隐私声明和接口权限。未完成这些检查时保持能力状态为未验证。
- 页面路径、分包名和 API 类型应引用统一常量或生成客户端，避免在多个页面复制协议字符串。
- API 环境统一由服务层解析；认证缓存必须与 API 环境绑定，切换环境、退出或换账号后不得沿用原会话或让迟到请求恢复旧身份。开发机回环地址不能直接当成真机可访问地址，不复制参考项目的服务器地址或凭据。
- 公开浏览不强制等待登录；需要身份的请求等待会话就绪。资料补全后返回原操作上下文，报名及其他状态变化后按实际需要刷新原页面，避免旧缓存继续显示可操作状态。
- 适配安全区、键盘、弱网、空状态、加载、错误和重复提交；触控目标和文案应适合微信端实际操作。

## 验证

- 纯代码变更至少做相关静态检查；依赖可用时运行 `pnpm --filter @huiju/miniapp type-check` 和必要构建。
- H5 预览、HBuilderX 运行、微信开发者工具和真机属于不同证据层级，分别记录。
- 涉及登录、手机号、分享、订阅消息或上传时，必须在有权限的微信环境中验证后才能称为通过。
- 不用占位数据、静态截图或编译成功代替真实接口与交互验收。
- 登录相关交付至少覆盖清缓存冷启动、分享直达、资料不完整、过期会话、切换环境、重复点击与返回刷新；清单和证据层级见 `docs/testing/README.md`（仓库根目录）。
