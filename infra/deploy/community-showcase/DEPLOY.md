# 有聚点展示数据与服务器部署

服务器 Agent 从用户交接的完整提交 SHA 取代码和展示内容。操作范围为部署有聚点 API、同步该提交涉及的后台产物、在有聚点业务库清理旧展示内容并导入新内容。小程序由用户另行编译上传。以下步骤需要在服务器执行，回执以实际结果为准。

## 确认目标和账号

1. 读取仓库根目录和 `apps/api` 的 AGENTS.md，核实 `huiju-api` 的工作目录、用户、环境文件和当前产物。执行 `git fetch origin main`，确认交接 SHA 属于 `origin/main`，在独立发布目录从这个 SHA 准备构建。保存当前服务版本、配置及后台静态目录，保留服务器工作区已有修改。
2. 核对目标 MySQL 实例、端口、库名及迁移表。使用参数化只读查询，确认用户私下指定的两个手机号分别只对应一个普通用户，且各自已有本小程序 AppID 的微信绑定，两个 member_id 不同。将脱敏的前后比对结果记入回执。遇到账号缺失、绑定缺失或重号，先保留原业务库并报告相应的手机尾号。缺失绑定的账号由其本人在现有小程序完成登录与绑定后再继续。
3. 保留目标账号原有 member_id、微信身份和平台配置，记录当前邀请码、社群编号与权限的可比对摘要。新旧版本可能有两处预期变化：0022 将旧邀请码换为六位数字，0023 建立学加社群编号。从这两条迁移完成起，以新值作为此次数据清洗基线。0026 新增的权限默认关闭，核对导入结果时区分既有权限和此次实际变动。
4. 记录活动、报名、到场、帖子与会员数量，核实服务器持久媒体路径和可用空间。核对数据库迁移记录与目标版本 `apps/api/drizzle/meta/_journal.json` 的顺序、时间和逐文件 SHA-256。已执行部分必须是完整前缀，最多推进至 0026。上次报告为 0020 时，待执行的是 0021 至 0026。遇到哈希不符、迁移缺口或部分 DDL，停止写入并报告差异。

## 构建、备份和迁移

在发布目录按锁文件构建，先确认生成 `apps/api/dist/main.js`。核对旧、新 SHA 之间后台及其构建依赖的变动，存在变动则同步构建并切换后台静态产物。

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @huiju/api build
# 需要同步后台时执行
corepack pnpm --filter @huiju/admin build
```

进入维护窗口，停止 `huiju-api` 及其他会写此库的作业。备份数据库、实际使用的持久媒体目录、上一版已运行产物与配置。备份保存在服务器受限目录，核对数据库导出结束标记、归档可读性和校验和。保持维护窗口直至核对完成，避免新报名落在快照与清洗之间。

如需迁移，在目标提交的 `apps/api` 下执行项目的 Drizzle migrator。以下命令用于部署代码与线上配置文件分开存放的环境，等同于仓库 `db:migrate` 的 Drizzle 入口。以已核对的系统环境文件替换路径，仅向该进程载入配置。

```sh
node --env-file=/etc/huiju/api.env ./node_modules/drizzle-kit/bin.cjs migrate
```

核对迁移表最终为 27 条，逐条匹配 0000 至 0026。特别核对 0021 资料列、0022 六位邀请码、0023 学加编号、0024 帖子阅读事件、0025 聚会人员字段和 0026 在册/管理身份。用只读方式再次记录两位用户的基线。MySQL DDL 可能在报错前已经提交，出现失败时保留现场，不直接重跑。

## 导入

回到目标提交的仓库根目录。以下命令使用 Bash，环境文件采用该服务器 `huiju-api` 的实际路径。以能读取配置、写入三处持久媒体目录并让 API 读取新文件的系统用户执行，确认当前 shell 未预设指向其他库的 `DATABASE_URL`。三个媒体变量 `LOCAL_AVATAR_DIRECTORY`、`LOCAL_COVER_DIRECTORY`、`LOCAL_CIRCLE_DIRECTORY` 使用系统服务实际的绝对路径。两位账号只通过本次进程环境传递。

```bash
read -rsp '第一位展示账号手机号：' SHOWCASE_PRIMARY_PHONE && printf '\n'
read -rsp '第二位展示账号手机号：' SHOWCASE_SECONDARY_PHONE && printf '\n'
export SHOWCASE_PRIMARY_PHONE SHOWCASE_SECONDARY_PHONE
node --env-file=/etc/huiju/api.env infra/deploy/community-showcase/import.mjs --check
```

检查退出码和范围，确认是授权的目标库及两位账号后，在同一 shell 执行一次：

```bash
node --env-file=/etc/huiju/api.env infra/deploy/community-showcase/import.mjs --apply
import_status=$?
unset SHOWCASE_PRIMARY_PHONE SHOWCASE_SECONDARY_PHONE
printf '导入退出码 %s\n' "$import_status"
test "$import_status" -eq 0
```

现场保留导入命令实际退出码和输出摘要。若连接中断或退出状态不明确，先回读业务库判断是否已经提交；成功导入后不要再次运行清洗来检查结果。原始密码、连接串、OpenID、会话、完整手机号不写入 Git 或部署回执。

## 核对与开放

- 比对两位指定用户在清洗前后的微信绑定、六位邀请码、社群编号与权限。分别回读其发起、报名、已到场数据及邀请关联。按活动核对报名计数和有效报名明细、到场标记，核对本月与累计榜的查询结果。实测手机号登录和操作权限由本人在小程序完成。
- 核对新活动时间、费用、对象说明和署名，检查各类帖子、读者、报名问题与答案、头像与海报所需封面。检查首屏广告及介绍页，报告仍有的旧内容。对实际新媒体文件抽样验证归属、服务账户可读性、URL、响应类型与非空图片。
- 原子切换应用目录并启动 `huiju-api`。等待服务就绪后通过本机和公网 HTTPS 分别访问 `/api/v1/health`、`/api/v1/activities`、`/api/v1/circle/posts`，回读这次导入的标题。用有效 TLS 访问实际媒体 URL 及后台登录页，核对证书与启动日志。记录失败项目，避免把受保护的读者名单、用户页或第三方接口仅凭健康响应写为通过。
- 回执包含部署 SHA、实际迁移范围、两位用户的脱敏核对、导入前后计数、代表性标题、媒体和 HTTPS 结果、备份位置、回退条件，以及等待用户在体验版验证的项目。

## 回退

切换前构建或只读检查失败时，保留现有服务。若维护期间迁移或导入失败且需回到此前版本，在停写状态下核对执行到哪一步，使用本次窗口的成套快照恢复数据库、媒体、配置与上一版运行产物后再验证。若已对外开放并产生新操作，先保全新增业务记录并报告影响，再决定恢复方式，避免整库恢复覆盖新报名。用原有代理与证书完成恢复后的内外网核对。

本批主要业务数据预期为 10 场聚会（6 场未来、4 场历史）、8 篇帖子、70 条报名、24 次到场。两位指定用户各发起 3 场、报名 7 场、到场 3 次。参加与发起均有记录；是否可发起新的活动仍取决于本社群在册身份。清理覆盖旧普通用户和活动、帖子、报名、交互及旧海报短码；保留两位指定用户、他们的邀请上级、平台编辑及其上级、平台与后台配置。旧分享可能无法打开。该批首场活动使用固定 ID，重复执行会跳过；可用 --check 回读。线上只使用本人已绑定的账号，手机尾号用于回执。
